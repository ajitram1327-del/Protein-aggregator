1. System Objective & Core Vision

Build a high-density, real-time commodity and retail price aggregator for sports nutrition (whey isolate, whey concentrate, casein, and plant proteins).

The platform operates like Sneakopedia, PCPartPicker, or a financial market terminal — not an e-commerce storefront or review blog. It is a multi-merchant intelligence matrix that maps SKUs across granular variant attributes (flavor, weight, formulation) and tracks the lowest real-time market ask, unit efficiency (cost per gram of pure protein), and historical retailer stock.



2. Design System & Hard Anti-Patterns

To prevent typical AI-generation defaults, the agent must strictly avoid the following patterns.

Banned: UI/UX & Styling
❌ Glassmorphism or backdrop-blur tricks (e.g. bg-white/10 backdrop-blur-md)
❌ Floating bubble/card grids with exaggerated rounded corners (rounded-2xl, rounded-3xl)
❌ Purple-to-blue / neon-pink / rainbow gradient buttons or background blurs
❌ Oversized decorative hero illustrations, stock 3D renders, or generic marketing fluff
❌ Low-contrast light grey text on white backgrounds (#9CA3AF on white for body text)
❌ Monotonous star ratings (5 yellow stars), testimonial carousels, fake urgency countdowns
❌ Mobile-first jumbo paddings (py-24, p-12) that push actionable data below the fold

Banned: Architecture & Logic
❌ Flat product listings — flavors and sizes must never collapse into a single flat price; prices map to distinct flavor + weight variants
❌ Missing unit economics — never display price alone without cost-per-gram of pure protein
❌ Dead affiliate buttons — actions must reflect live inventory status (disabled/dimmed when out of stock)

2.1 Design System & Aesthetic Foundation
Structural Grid & Border Layout
Strict 1px solid borders (#E5E7EB light mode, #262626 dark mode)
Sharp micro-radii (0px / square, max rounded-sm)
High-contrast neutral palette: off-white background (#F8F9FA / #0A0A0A), near-black text (#111827 / #F9FAFB)
Typography & Data Alignment
Sans-serif for titles: System sans / Inter / Geist (font-sans)
Monospace for all data fields: JetBrains Mono, Roboto Mono, or system mono (font-mono) — SKUs, prices, specs, timestamps, stock status
Information Density First
Actionable tabular data must render within the first screen height (above the fold)
Compact table rows (py-2.5 to py-3), not large individual cards
Variant selector emulates an interactive stock matrix (Sneakopedia-style size grid): flavor, tub weight, serving count, minimum ask price per tile



3. Relational Database Schema & Deterministic Hashing (PostgreSQL / Supabase)

3.1 Deterministic Hashing Specification

To eliminate duplicate variants across divergent e-commerce listings, the system MUST compute a deterministic hash string before variant insertion. Input text MUST be normalized: lowercased, whitespace-trimmed, non-alphanumeric characters stripped.

$$\text{Variant Hash} = \text{SHA256}(\text{product\_id} \mathbin{\Vert} \text{weight\_in\_grams} \mathbin{\Vert} \text{canonical\_flavor})$$

import reimport hashlibfrom pydantic import BaseModel class NormalizedVariant(BaseModel):    weight_grams: int    canonical_flavor: str    variant_hash: str class VariantNormalizer:    FLAVOR_CANONICAL_MAP = {        r"rich choco.*|double rich.*|belgian choco.*|chocolate fudge|dark choco.*": "chocolate",        r"vanilla.*|french vanilla|creamy vanilla": "vanilla",        r"alphonso mango|mango swirl|mango": "mango",        r"cafe mocha|coffee|espresso|cappuccino": "coffee",        r"unflavored|raw|natural|naked": "unflavored",        r"strawberry.*|berries": "strawberry",        r"kulfi|kesar pista": "kesar_pista"    }     @staticmethod    def parse_weight(raw_title: str) -> int:        match = re.search(r"(\d+(?:\.\d+)?)\s*(kg|g|lbs|lb|oz)", raw_title, re.IGNORECASE)        if not match:            return 1000         val, unit = float(match.group(1)), match.group(2).lower()        if unit == 'kg': return int(val * 1000)        elif unit == 'g': return int(val)        elif unit in ('lb', 'lbs'): return int(val * 453.592)        elif unit == 'oz': return int(val * 28.3495)        return 1000     @classmethod    def parse_flavor(cls, raw_title: str) -> str:        for pattern, canonical in cls.FLAVOR_CANONICAL_MAP.items():            if re.search(pattern, raw_title, re.IGNORECASE):                return canonical        return "unflavored"     @classmethod    def execute(cls, product_id: str, raw_title: str) -> NormalizedVariant:        weight_g = cls.parse_weight(raw_title)        flavor = cls.parse_flavor(raw_title)        raw_signature = f"{product_id}_{weight_g}_{flavor}".lower().strip()        v_hash = hashlib.sha256(raw_signature.encode('utf-8')).hexdigest()         return NormalizedVariant(weight_grams=weight_g, canonical_flavor=flavor, variant_hash=v_hash)

5.2 Label Discrepancy Logic

The pipeline compares parsed OCR metrics against scraped retailer text:

$$\Delta_{\text{servings}} = \vert{}\text{scraped\_servings} - \text{ocr\_servings}\vert{}$$

If $\Delta_{\text{servings}} > 0$ or the protein variance exceeds 1.0g, the system persists the OCR values as the canonical source-of-truth.



6. Scientific Analytics & Equalizer Computation Engine

6.1 Bioavailability Mathematical Specifications

The analytics engine standardizes all products into an absolute cost of biologically useful protein.

$$\text{Absorbed Protein (g)} = \text{Label Protein per Serving (g)} \times \text{DIAAS Multiplier}$$

$$\text{Effective Yield Cost (₹/g)} = \frac{\text{Current Lowest Price (INR)}}{\text{Total Servings} \times \text{Absorbed Protein (g)}}$$

$$\text{Flavor Tax (\%)} = \left( \frac{\text{Effective Yield Cost}_{\text{flavored}}}{\text{Effective Yield Cost}_{\text{unflavored}}} - 1 \right) \times 100$$

6.2 Analytical Calculator Implementation

class EqualizerEngine:    # Based on FAO-recommended clinical digestibility standards    DIAAS_INDEX = {        "whey_isolate": 1.09,        "whey_concentrate": 0.98,        "casein": 1.18,        "soy": 0.90,        "plant_blend": 0.85, # Synergistic Pea + Rice formulation        "pea_isolate": 0.82,        "rice_protein": 0.42    }     @classmethod    def calculate_metrics(        cls,        category: str,        price_inr: float,        label_protein_g: float,        serving_size_g: float,        total_servings: int,        unflavored_cost_per_g: float = None    ) -> dict:        diaas = cls.DIAAS_INDEX.get(category, 0.80)        absorbed_protein_per_serving = round(label_protein_g * diaas, 2)        total_absorbed_protein = absorbed_protein_per_serving * total_servings        effective_cost_per_g = round(price_inr / total_absorbed_protein, 2) if total_absorbed_protein > 0 else 0.0        purity_pct = round((label_protein_g / serving_size_g) * 100, 2) if serving_size_g > 0 else 0.0         flavor_tax_pct = 0.0        if unflavored_cost_per_g and unflavored_cost_per_g > 0:            flavor_tax_pct = round(((effective_cost_per_g / unflavored_cost_per_g) - 1.0) * 100, 2)         return {            "diaas_score": diaas,            "absorbed_protein_per_serving_g": absorbed_protein_per_serving,            "total_absorbed_protein_pool_g": total_absorbed_protein,            "effective_cost_per_bioavailable_g_inr": effective_cost_per_g,            "scoop_purity_pct": purity_pct,            "flavor_tax_pct": max(flavor_tax_pct, 0.0)        }

Objective: Evolve the platform from a price aggregator into a defensive intelligence terminal. The system MUST algorithmically detect formulation deception, bot manipulation, counterfeit risks, and extreme pricing arbitrage to protect consumer health and budgets.

10.1 Proprietary Blend Exposer (Fairy-Dusting Detection)

File Path: src/analytics/ingredient_auditor.py
Execution Paradigm: NLP-based sequence evaluation governed by FSSAI descending-weight mandates.
Algorithmic Procedure:
Ingest comma-separated raw ingredient string from OCR or scraped HTML payload.
Normalize string (lowercase, strip brackets).
Map array indices of predefined FILLERS (maltodextrin, taurine) and premium ACTIVES (citrulline, whey isolate).
Evaluation Rule: If Index(FILLER) < Index(ACTIVE), flag is_fairy_dusted = True.
Compute trust_score deduction (-15 points per unique violation).

Agent Directive: Bind output to products.trust_score and expose violation strings in the Next.js Due Diligence modal.

10.2 Near-Expiry Clearance Arbitrage

File Path: src/analytics/expiry_arbitrage.py
Execution Paradigm: Temporal consumption forecasting vs. expiration delta.
Algorithmic Procedure:
Parse expiry_date from e-pharmacy DOM (e.g., Tata 1mg, Apollo).
Calculate months_to_expiry relative to current system time.
Calculate months_to_finish = (total_servings / user_scoops_per_day) / 30.
Evaluation Rule: is_safe_for_consumption ONLY IF months_to_expiry > (months_to_finish + 1.0) (strict 1-month safety buffer).
is_clearance IF discount > 25% AND months_to_expiry ≤ 5.

Agent Directive: Build a dedicated /clearance API route and Next.js feed that surfaces ONLY items passing the is_safe_for_consumption check.

10.3 Review Authenticity Engine (Bot-Filtering)

File Path: src/vision/review_authenticity.py
Execution Paradigm: Lexical Jaccard Similarity and Temporal Clustering.
Algorithmic Procedure:
Siphon the most recent 100 5-star reviews for a given SKU.
Cluster Audit: Traverse sorted timestamps. If ≥5 reviews occur within a ≤24-hour delta window, increment temporal_cluster_flags.
Lexical Audit: Execute pairwise Jaccard similarity comparison across all 5-star texts. If overlap > 0.65, increment copy_paste_flags.
Penalty Formula: Authenticity Score = 100 - (clusters * 10) - (copy_pastes * 5).

Agent Directive: Render the Authenticity Score as a progress bar. If score < 60, overlay a High Bot Risk warning.

10.4 Marketplace Seller Trust Matrix

File Path: src/pipeline/seller_matrix.py
Database Requirement: Query against seller_trust_registry whitelist table.
Algorithmic Procedure:
Scrape sold_by DOM node from third-party marketplaces (Amazon, Flipkart).
Normalize seller string and cross-reference against static AUTHORIZED_DISTRIBUTORS array (e.g., Cocoblu, SuperComNet) OR verify direct brand storefront naming.
Evaluation Rule: If match fails, mutate price_listings.is_authorized_seller to False.

Agent Directive: UI MUST visually segregate unauthorized sellers. If an unauthorized seller holds the lowest price, the frontend MUST NOT use it for the primary "Lowest Price" badge — default to the lowest *authorized* price.

10.5 Independent Lab Scorecard (NABL Integration)

File Path: src/compliance/lab_auditor.py
Database Requirement: Query against independent_lab_tests table.
Algorithmic Procedure:
Calculate Protein Variance: ((lab_yield - label_yield) / label_yield) * 100.
Check against FSSAI maximum thresholds: Lead (Pb) ≤ 2.5 mg/kg, Arsenic (As) ≤ 1.1 mg/kg.
Evaluation Rule: passed_audit = True IF variance ≥ -5.0% AND heavy metals ≤ thresholds.

Agent Directive: Display a prominent 🛡️ 3rd-Party Lab Verified Gold Shield for passing products, with a hyperlink to the raw PDF report_url.

10.6 Glitch Price Webhook Engine (Extreme Arbitrage)

File Path: src/notifications/webhook_engine.py
Integration: Discord / Telegram Webhook API.
Algorithmic Procedure:
On every price insertion, query PostgreSQL for the 90-day moving average of current_price_inr for that variant_id.
Calculate discount delta from the moving average.
Evaluation Rule: If delta > 30% AND is_authorized_seller == True, generate a Markdown-formatted alert payload.
Dispatch POST request to the webhook endpoint with product name, flash price, normal price, and outbound affiliate URL.

Agent Directive: Execute webhook asynchronously to avoid blocking the main ingestion pipeline thread.



11. Cross-Product Compare Engine

Objective: Let users evaluate multiple SKUs — across brands, not just within one product's variants — side by side on the same normalized metrics the Equalizer Engine already produces. This is the platform's PCPartPicker moment: the single highest-leverage feature for driving shareable, high-intent traffic.

11.1 Comparison Snapshot Schema (Optional Persistence)

File Path: DDL addition to 3.2

-- Table 4: Shareable Comparison SnapshotsCREATE TABLE comparison_snapshots (    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),    variant_ids UUID[] NOT NULL CHECK (array_length(variant_ids, 1) BETWEEN 2 AND 4),    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),    expires_at TIMESTAMPTZ NOT NULL DEFAULT (NOW() + INTERVAL '90 days')); CREATE INDEX idx_snapshots_expiry ON comparison_snapshots(expires_at);

11.2 Comparison API Route

File Path: src/app/api/compare/route.ts
Algorithmic Procedure:
Accept variantIds query param (2–4 UUIDs) or a snapshotId.
For each variant, fetch: EqualizerEngine.calculate_metrics output (6.2), trust_score (10.1), Authenticity Score (10.3), is_authorized_seller lowest-price offer (10.4), passed_audit lab status (10.5).
Return a normalized JSON array, one object per variant, keyed identically so the frontend can render aligned rows.
If variantIds provided (not a snapshot), optionally persist to comparison_snapshots and return the new snapshotId for URL sharing.

11.3 Frontend Compare Tray & Table

File Path: components/CompareTray.tsx, app/compare/page.tsx
UI Directives:
A persistent floating "Compare Tray" — a + Compare action on every product card/row, capped at 4 active slots, following the same square-border/monospace design system as 2.1.
Route: /compare?ids=variantId1,variantId2,... or /compare/[snapshotId] — both shareable and bookmarkable.
Table rows, aligned across compared variants: Effective Cost per Bioavailable Gram (sort/highlight lowest), DIAAS Score, Scoop Purity %, Flavor Tax %, Trust Score, Authenticity Score, Lab-Verified badge, FSSAI warning status, Lowest Authorized Price + platform.
A compact horizontal bar chart of ₹/g effective cost across the compared set, rendered above the table.
Per Anti-Pattern rules in Section 2: no missing unit economics — every compared row must show cost-per-gram, never raw price alone.

Agent Directive: Reuse ProductListingView (8.1) as the shared shape for each compared row; do not introduce a parallel type.
